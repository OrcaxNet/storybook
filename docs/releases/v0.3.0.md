# Storybook v0.3.0

召回反馈飞轮：像产品埋点一样从 Agent 会话中离线挖掘"记忆是否真的有用"，不新增任何需要 Agent 主动调用的反馈工具。

- 召回埋点：MCP `recall` / `prime_context` 与 `book prime` hook 在本地库记录 `recall_events` / `recall_exposures`（曝光、名次、分数）；`get_story` 记为对最近一次曝光的点击。CLI、评测与基准路径不记录。
- 离线采纳判定：做梦周期按会话时间窗与工作区指纹关联召回事件，由生成模型判定每条记忆 used / ignored / misleading，并记录"会话需要但记忆库缺失"的经验缺口。每个会话至多一次生成调用；`STORYBOOK_ADOPTION_JUDGE_ENABLED=0` 可关闭。
- 排名：Beta 平滑的采纳先验对分数做有界调节（`STORYBOOK_ADOPTION_SCORE_WEIGHT`，默认 0.06），被判 misleading 额外扣分；未判定记忆保持中性。
- `co_recall` 边改由"共同采纳"产生；曝光默认只计 `access_count`，避免"排名靠前 → 更常曝光 → 边更强"的自我强化。设 `STORYBOOK_RECALL_EXPOSURE_REINFORCE=1` 恢复 v0.2 行为。
- `book memory feedback`：曝光 → 点击 → 采纳漏斗、低采纳记忆、零结果查询与记忆缺口。
- MCP 返回精简：`recall` 默认只返回精简环境摘要，检索诊断（`rerank_trace`、`query_plan`、`latency_ms`、`graph_trace`、`score_components` 等）移到 `verbose=true`；`get_story` 修订链默认不含快照；`prime_context` 不再回传完整 ContextEnvelope。典型 recall 负载减少约 70%。
- 关键词去噪：Codex 适配器剥离无路径的 `# AGENTS.md instructions` 块、`<in-app-browser-context>` 与 `## My request:` 头；关键词提取与合并过滤 `AGENTS.md`、`storybook.recall` 等注入指令噪声。存量记忆用 `book memory clean-keywords --apply` 清理（会重算向量）。

升级后重启 MCP 客户端（Claude Code / Codex / Cursor 等）以加载新 server，并运行一次 `book memory clean-keywords --apply` 清理存量噪声关键词（新会话自动生效，历史会话不会重新加工）。
