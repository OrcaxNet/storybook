# Storybook v0.2.0

模型配置统一为当前 Profile 的 `model-config.json`。LLM 与 embedding 分别使用
`(protocol, base_url, secret, model)` 四元组，可直接组合第三方 LLM 与本地 Ollama embedding。

## 模型配置

- 按请求协议选择 `openai`、`anthropic` 或 `ollama`，不再按服务厂商分类；embedding 支持 `openai` 与 `ollama`。
- `book init` 向导依次填写四个字段，embedding 默认继承前一组；空 secret 可显式清除继承的密钥。
- `book init --config <file>` 将 JSON 配置导入当前 Profile；`book config --path` 查看实际路径，`book config` 查看遮蔽密钥的配置。
- 两个端点独立探测、鉴权和调用；首次创建索引自动检测 embedding 维度。
- 模型文件使用 `0600` 权限，公开配置与诊断遮蔽 secret；索引重建期间保留当前 serving 端点与凭据快照。

## 升级步骤

此版本移除了旧的模型环境变量、provider/preset 和旧版模型配置文件格式。
升级后请使用 [配置示例](https://github.com/OrcaxNet/storybook/blob/v0.2.0/model-config.example.json)
填写两组四元组，再运行：

```bash
book init --config model-config.json
book config
book doctor
```

`generation` 必须完整填写；`embedding` 对象中省略的字段继承 generation，`"secret": ""` 清空密钥。
导入后修改 `book config --path` 返回的文件，并重启已运行的 MCP server 或 watch/daemon 进程。

已有 Profile 应先保持原 embedding 的协议、地址、模型和维度。更换 embedding 时，创建隔离 Profile，
或按 [README 的索引重建流程](https://github.com/OrcaxNet/storybook/blob/v0.2.0/README.md)
重建向量；初始化不会将不同模型空间混入已有索引。Profile 目录与算法参数仍可使用 `.env.example` 中的环境变量。

## 自 v0.1.3 起的其他更新

- 提供 `book` 命令入口与统一的命令分组。
- 新增 `book version` 和 `book update`，支持版本查询与校验下载后的原子升级。
- `--verbose` 输出带阶段标签的检索日志。
- 改进 Python/venv 安装诊断，稳定检索超时降级测试。
